# Island Airfields v44 — кандидат в публичную бету

Версия для Windows и Carrier Command 2 1.5.18, с CC2X 0.2.0.
Самолёты и вертолёты садятся на аэродромы захваченных островов, обслуживаются
в ангарах и взлетают по новому приказу. Самолёты используют полосу по очереди.

Это экспериментальный выпуск. Между полосой/площадкой и ангаром ещё есть переносы;
полноценная рулёжка будет отдельным изменением. В этот кандидат новые алгоритмы
полёта не добавляются. Multiplayer ещё не прошёл приёмку; VR, dedicated server
и macOS не поддерживаются.

## Установка и отключение

Закрой игру. Скопируй три файла из `game folder` к `carrier_command.exe`, а папку
`mods/Island Airfields` — в `%APPDATA%\Carrier Command 2\mods`. Включи Island Airfields
в меню модов. Используй одну Lua-копию: Workshop, локальную или из пакета.

Сначала сохрани имеющиеся DLL и INI. Чужой `dinput8.dll` нельзя просто заменить:
другой загрузчик и CC2X используют одно имя. При обновлении можно оставить свой INI.

Чтобы отключить мод, при закрытой игре переименуй `cc2x_island_airfields.dll`
в `cc2x_island_airfields.dll.disabled` и выключи Island Airfields в меню модов.
Для включения верни имя DLL и включи мод. Сам CC2X можно оставить другим плагинам.

В `cc2x_island_airfields.ini` параметр `experimental_planes=0` оставляет только
вертолёты, `1` разрешает самолёты. `plane_assist=1` оставляет помощь при полёте.
Настройки применяются после перезапуска игры. Выбранные значения записаны
также в `release-manifest.json`.

## Что проверено к подготовке кандидата

- В игровом журнале установленной v44 есть успешные посадки и взлёты обоих типов
  авиации. Handoff сообщает прежний результат 7/7 на тестовом сохранении;
  это история испытаний, а не новая приёмка этого архива.
- Релизный скрипт проверяет PE32 DLL, версии, состав архива и хеши всех файлов.
- При упаковке из установленной игры фиксируется именно используемая пара DLL.
  Это важно: имеющийся `sdk/dist/dinput8.dll` отличается от установленного.
- В коде `fd_test.py` исправлен код выхода: наличие FAIL теперь даёт ненулевой
  результат, чтобы автоматическая проверка не принимала неудачу за успех.
- Исходники ядра и плагина отдельно пересобраны Zig 0.15.2: компиляция прошла.
  Хеши полученных DLL отличаются от установленных; причину отличий пока не
  установили. Различие хешей само по себе не доказывает различие игрового поведения.
  Кандидат сохраняет установленную пару. В `BUILD_CHECK.json` записаны хеши
  исходников и обеих пар DLL. Новые бинарники в игру не устанавливались.

Игровые DLL и текущие приказы техники при подготовке пакета не меняются.
Проверка упаковки не доказывает успешность сценариев в движке.

## Перед публикацией

1. Установить кандидат из ZIP в чистое тестовое окружение и проверить отключение
   и обратное включение. Прозрачная установка одним щелчком ещё требует подготовки;
   текущий пакет использует описанное выше ручное копирование.
2. На отдельном сохранении прогнать взлёт/посадку лёгких и тяжёлых самолётов
   и вертолётов, два самолёта на одной полосе, отмену приказа и повторную загрузку
   посреди посадки. Сохранить вывод `native/tools/fd_test.py` и свежий `cc2x.log`
   вместе с SHA-256 проверяемых DLL. Пока новая приёмка не выполнена.
3. Подтвердить лицензию нового CC2X и плагина для публикации исходников: явного
   LICENSE для текущей реализации нет. MIT из заархивированного старого SDK
   не выдаётся за лицензию переписанного проекта. Тексты зависимостей приложены.
4. Установить происхождение различий пересобранных и замороженных DLL либо
   провести игровую приёмку новой пары из приложенных исходников и зафиксировать
   уже её в следующем кандидате. Сам факт успешной компиляции недостаточен.
5. Опубликовать как бету с этим списком ограничений, версией, хешами и инструкцией
   по отчётам. Файлы игры, сохранения, логи пользователей и исследовательские
   выгрузки в публичный архив не включать.

Публикация из этого рабочего дерева автоматически не выполняется.
